# 数据留存与删除政策

> 这份文档回答两个必答题：**我们留了什么、留多久**，以及**用户要求删除时我们怎么删**。
> 每一项都指到具体代码，便于核验；写不出代码位置的条目不应写进这份文档。

## 一、留存哪些数据

| 数据类别 | 内容 | 留存期 | 实现 |
|---|---|---|---|
| 成片与交付物 | MP4/GIF、音轨、分镜图、manifest | **30 天** | `retention.DEFAULT_TTL_DAYS`（`FINAL_VIDEO/GIF/AUDIO/STORYBOARD/MANIFEST`） |
| 镜头片段 | 每个镜头的 MP4 | **7 天** | `retention.DEFAULT_TTL_DAYS[VIDEO]` |
| 关键帧 | 每镜首帧 PNG | **7 天** | `retention.DEFAULT_TTL_DAYS[KEYFRAME]` |
| 线索基准图 | 角色/场景/道具设定图 | **30 天** | `retention.DEFAULT_TTL_DAYS[BASE_IMAGE]` |
| 项目与剧本 | 用户输入的原始文案、分镜结构 | 账号存续期 | `projects` 表 |
| 额度账本 | 每一次扣费/退还 | **长期保留**（见第三节） | `ledger_entries`（只追加） |
| 用量记录 | 按镜头的成本归因 | 长期保留 | `usage_records` |
| 审计日志 | 认证、密钥、计费、删除等动作 | **≥ 6 个月**（网络安全法要求） | `audit_logs`（链式哈希） |
| 应用日志 | 请求日志、结构化事件 | 由部署侧日志平台决定，默认 30 天 | `observability.logging` |

**GC 如何执行**：worker 每 10 分钟扫一次 `artifacts.expires_at <= now()` 的记录，
删除对象存储文件并置 `deleted_at`（软删，可审计）。
实现：`reelagent_cloud/services/retention.py::gc_expired_artifacts`，
接线：`workers/runner.py::_housekeeping`。

**为什么不回收「运行中任务」的产物**：任务可能跑很久，早期片段到期后若被删，
正在生成的成片会突然缺片段。GC 显式排除未终结任务名下的产物。

## 二、账号注销时做什么

用户调用 `DELETE /api/v1/me` 并重新输入密码后，按以下顺序执行
（实现：`reelagent_cloud/services/account.py::delete_account`）：

1. **取消活跃任务** —— 不取消的话，删完数据任务仍在跑，会把产物写回来
2. **清除产物对象** —— 先删文件再删记录，避免「记录没了文件还在」
3. **软删项目** —— 保留行以便审计追溯，业务上不可见
4. **吊销全部 API Key** —— 否则注销后旧 Key 仍能调接口
5. **匿名化用户** —— 邮箱改写为 `deleted-{id}@deleted.invalid`，口令置随机，
   会话代际 +1（已签发 Cookie 立即失效）
6. **停用组织** —— `is_suspended = true`，阻断一切入口
7. **写审计** —— 最后写，确保前面每一步都留痕

**多成员组织不允许自助注销**：一个人的注销不该摧毁其他成员的数据。
这种情况要求先移除成员或转移数据（实现：`account.assert_can_delete`）。

## 三、为什么账本不删

《电子商务法》与会计档案管理要求交易记录保留一定年限。
所以**账本与用量记录保留**，但其中的用户身份已随第 5 步匿名化，
无法再关联到自然人。

这个取舍必须写进对外隐私政策，否则就是「声称删除但实际保留」——
那是比不做更严重的问题。

## 四、留存的边界条件（如实披露）

- 备份中的历史副本：按备份周期自然过期，不单独清理。备份保留期见 `docs/DEPLOYMENT.md`。
- 审计链的历史记录：本功能上线前的审计没有哈希（`entry_hash = ""`），
  校验时从第一条有哈希的记录开始。**不回填历史哈希** —— 伪造历史哈希
  等于伪造证据，比承认「这段没有链」更糟。
- 保留期配置项 `0` 表示**关闭回收**（不是「立刻删」）。语义刻意偏保守，
  避免一次误配把线上产物清空。
